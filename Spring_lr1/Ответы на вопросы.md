### **Вопрос 2: Чем отличаются языки программирования Java и Kotlin?**

1. Синтаксис:
   - Kotlin имеет более лаконичный и выразительный синтаксис по сравнению с Java. Например, в Kotlin можно писать меньше кода для выполнения той же задачи благодаря возможности использовать инференцию типов, короткие объявления методов, однострочные функции и операторы нулевых значений.

2. Нулевые значения:
   - В Kotlin есть встроенная система работы с nullable типами, что предотвращает классическую ошибку NullPointerException в Java. Переменные и параметры по умолчанию не могут принимать null, что вынуждает разработчиков явно указывать nullable типы с использованием ?.

3. Совместимость с Java:
   - Kotlin полностью совместим с Java. Это означает, что можно легко вызывать код на Java из Kotlin и наоборот. Это упрощает переход на Kotlin для существующих Java-проектов.

4. Корутинные функции:
   - Kotlin предоставляет встроенную поддержку асинхронного программирования через корутины, что позволяет управлять асинхронными задачами гораздо проще, чем в Java, где обычно для этого используются Threads, CompletableFuture, или ExecutorService.

5. Стандартные функции и расширения:
   - В Kotlin можно добавлять функции к существующим классам (так называемые extension functions), что позволяет расширять стандартные классы и интерфейсы без необходимости их изменять или наследоваться от них.

### **Вопрос 4: Чем отличаются языки программирования Kotlin и Groovy?**

1. Статическая vs динамическая типизация:
   - Kotlin является статически типизированным языком, что означает, что типы переменных проверяются на этапе компиляции.
   - Groovy, напротив, является динамически типизированным языком, позволяя переменным менять свои типы во время выполнения программы.

2. Производительность:
   - Из-за статической типизации и дополнительных оптимизаций компилятора, Kotlin, как правило, показывает лучшую производительность, чем Groovy, который делает проверки типов на этапе выполнения.

3. Поддержка асинхронности:
   - Kotlin поддерживает корутины для асинхронного программирования, как мы уже упомянули. В Groovy нет встроенной поддержки корутин, хотя можно использовать потоки или сторонние библиотеки для реализации асинхронного поведения.

4. Совместимость с Java:
   - Оба языка совместимы с Java, но Kotlin поддерживает интероперабельность с Java на более высоком уровне. Код на Kotlin можно комбинировать с Java без каких-либо проблем, что не всегда гарантируется в Groovy.

5. Применение:
   - Kotlin используется в первую очередь для разработки Android-приложений, а также как альтернатива Java в серверных приложениях.
   - Groovy чаще используется в скриптинге, автоматизации задач, а также в проектах, связанных с фреймворком Gradle и тестированием (например, Spock).

### **Вопрос 6: Что нового добавилось в Java 17 в отличие от Java 11?**

1. Sealed classes (Запечатанные классы):
   - В Java 17 добавлена поддержка sealed classes, которые позволяют ограничивать круг классов, которые могут наследоваться от данного класса. Это полезно для более строгого контроля наследования и повышения безопасности кода.

2. Pattern matching для `instanceof`:
   - В Java 17 продолжена оптимизация механизма pattern matching. Теперь можно использовать сопоставление с образцом при использовании оператора instanceof, что упрощает работу с приведением типов.

3. Records:
   - В Java 16 были добавлены Records — новый способ определения классов с неизменяемыми данными. Они позволяют писать компактные и безопасные классы для хранения данных без необходимости вручную писать конструкторы, геттеры и методы equals, hashCode и toString.

4. Текстовые блоки:
   - В Java 13 были введены текстовые блоки (text blocks), а в Java 17 они получили окончательную реализацию. Это упрощает работу с многострочными строками, позволяя избегать ручного экранирования символов.
5. Поддержка MacOS AArch64:
   - В Java 17 добавлена поддержка процессоров на архитектуре ARM64 (AArch64) для MacOS, что делает Java более совместимой с новыми системами на базе Apple Silicon (M1, M2).

6. Garbage Collectors:
   - В Java 17 улучшены алгоритмы сборки мусора, особенно ZGC (Z Garbage Collector), который стал более производительным и эффективным.
